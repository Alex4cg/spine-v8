## 1. Общая структура игры

- **Папка игры**: `examples/slots/slot_972_Zeus_3_Pots/`
  - `assets/` – Spine, текстуры, звуки
  - `source/` – код игры (TS/JS)
  - `matrix/` – сценарии (JSON) для дебага/тестов
  - `docs/` – документация по слоту (включая этот файл)
- **Режимы**:
  - **Regular Game** – обычные спины
  - **Bonus Hold & Win** – бонус с фиксацией символов
- **Главный контроллер**: `ZeusGame`
  - Состояния: `regularIdle`, `regularSpin`, `regularResolve`, `transitionToBonus`, `bonusIntro`, `bonusSpin`, `bonusEnd`
  - Управляет генераторами сценариев, полем, горшками, UI и переходами между режимами

---

## 2. Поле 3×3 и символы

- **Матрица**:
  - Логика генераторов: `grid[row][col]` (0–2, 0–2)
  - Визуальный слой: можно хранить `grid[col][row]` с конвертацией (как в slot_5)
- **Типы символов (черновик)**:
  - `0..N` – обычные символы (low/high)
  - Отдельные индексы под спец-символы:
    - символы, которые бьют в горшки (монеты/молнии)
    - спец-символы для бонуса Hold & Win (фиксация, джекпоты и т.п.)
- **Отрисовка поля**:
  - 3×3 ячейки, каждая – отдельный `CellView`:
    - локальная «лента» внутри ячейки (вращение в своей ячейке, а не общая колонка)
    - Spine/спрайтовый символ поверх ленты
  - Вращение реализуем как анимацию внутри каждой ячейки: скролл текстур/спрайтов вниз/вверх + смена итогового символа по сценарию

---

## 3. Накопители-горшки (Spine сверху)

- **Расположение и структура**:
  - 3 горшка над тремя колонками (по одному на колонку)
  - Каждый горшок – отдельный Spine:
    - анимации: `idle`, `fill`/`hit`, `win`, `empty`, возможно `highlight`
- **Модель состояния горшка**:
  - Параметры в коде: `currentValue`/`multiplier`, `isFull`, `isActiveInBonus`
  - Spine только отображает состояние (через анимации/слоты), логика – в коде
- **Связь с полем и бонусом**:
  - При выпадении спец-символа в колонке:
    - сценарий описывает событие накопления: `collectorEvents` или `flights` (см. раздел про перелёты)
    - игра обновляет модель горшка и запускает Spine-анимацию `fill`
  - При выполнении условий (например, суммарный множитель/количество ударов):
    - сценарий выставляет флаг `bonusTrigger`
    - `ZeusGame` запускает переход в бонус Hold & Win

## 4. Два генератора сценариев

### 4.1. Regular Scenario Generator (3×3)

- **Класс**: `ZeusRegularScenarioGenerator`
- **Базируемся на идеях `ScenarioGeneratorV3`**:
  - Формат событий похож на slot_5:
    - `event` (`spin`, `spin-win`, при желании упрощённые `cascade`-события или без каскадов)
    - `grid` (`row`×`col`)
    - `groupMarkup`, `winningGroups`, `payouts`, `totalPayout`
  - Добавляем Zeus-специфичные вещи:
    - `collectorEvents` / `flights` для ударов по горшкам, например:
      ```ts
      collectorEvents: Array<{
        fromCell: { row, col }
        potIndex: number
        value: number
        type: 'coin' | 'lightning'
      }>
      ```
    - `bonusTrigger: boolean` – флаг перехода в бонус
- **Волатильность и частоты**:
  - Параметры по аналогии со `ScenarioGeneratorV3`:
    - `simpleSpinChance`, `minSimpleSpinsBeforeWin`, `maxCascadeSteps` (если будут каскады)
  - Адаптация под маленькое поле 3×3 (меньше символов, более управляемые комбинации)

### 4.2. Bonus Hold & Win Scenario Generator

- **Класс**: `ZeusBonusScenarioGenerator`
- **Особенности**:
  - Отдельная матрица бонуса (скорее всего тоже 3×3, но с другим набором символов – значения монет, спец-мультипликаторы, джекпоты)
  - Каждый респин – отдельный шаг сценария:
    - `event`: `bonus-spin`, `bonus-spin-win`, `bonus-end`, `bonus-jackpot` и т.п.
    - `grid`: бонусные символы (номиналы/мультипликаторы)
    - `lockedCells`: какие ячейки зафиксированы
    - `respinsLeft`, `totalBonusWin`
    - возможные флаги: `jackpotMinor`, `jackpotMajor` и др.
- **Логика Hold & Win**:
  - На старте бонуса часть ячеек уже заполнена (сумма из горшков)
  - На каждом респине:
    - пустые ячейки заполняются монетами/множителями по заданным шансам
    - если выпал хотя бы один новый бонусный символ – `respinsLeft` сбрасывается до начального значения
    - при отсутствии новых символов – `respinsLeft--`
    - при `respinsLeft === 0` – событие `bonus-end`, финальный подсчёт

## 5. Менеджер поля и Spine-анимаций

- **Поле (`ZeusField`)**:
  - Знает координаты 3×3 ячеек и горшков
  - Принимает шаг сценария и:
    - запускает спины по ячейкам
    - помечает выигрышные символы (по `groupMarkup`)
    - инициирует перелёты/удары по горшкам (по `collectorEvents`/`flights`)
- **Spine-менеджер**:
  - Общий helper по `SPINE_PIXI_GUIDE.md`:
    - создание через `Spine.from({ skeleton, atlas })`
    - заглушка `skeleton.physics`
    - `setSkin()` + `setSlotsToSetupPose()`
    - не трогаем `update()` вручную, используем `zIndex` + `sortChildren()`
  - Для временных Spine (перелёты, вспышки и т.п.):
    - жёсткий порядок уничтожения: `removeChild` → `state.clearTracks()` → `destroy({ children: true })` в `requestAnimationFrame`

## 6. Перелёты (от ячеек к горшкам)

- **Данные сценария**:
  - Расширить события регулярной игры:
    ```ts
    flights: Array<{
      fromCell: { row, col }
      toPotIndex: number
      value: number
      type: 'coin' | 'lightning' | 'jackpot'
    }>
    ```
- **Анимационный слой (`ZeusFlightSystem`)**:
  - Создание Spine-объекта перелёта (по аналогии с `collect_effect` из документации)
  - Использование контрольных костей/Bezier-траекторий:
    - точки старта – ячейки поля
    - точки окончания – соответствующие горшки
  - События Spine (`collect_effect_hit` / свои) используются, чтобы:
    - в момент попадания обновить модель горшка
    - запустить анимации `fill`/`hit` на горшке
    - при необходимости триггерить дополнительные эффекты (молнии Зевса, вспышки и т.п.)

## 8. Машина состояний и переходы между режимами

- **Состояния `ZeusGame`**:
  - `regularIdle` → ожидание нажатия SPIN
  - `regularSpin` → проигрывание анимаций спина по сценарию
  - `regularResolve` → выдача выигрыша, перелёты, удары по горшкам
  - `transitionToBonus` → если `bonusTrigger`, проигрываем переход
  - `bonusIntro` → старт бонуса (intro-анимации, установка стартовой бонусной сетки)
  - `bonusSpin` → цикл респинов Hold & Win
  - `bonusEnd` → финальный подсчёт, анимации выигрыша, возврат к `regularIdle`
- **Transition-анимации**:
  - При входе в бонус:
    - отдельная Spine-анимация Zeus/молний + затемнение/смена фона
    - отключение регулярной сетки, включение бонусной
  - При выходе:
    - короткая анимация (вспышка + подсчёт) и возврат к обычному фону/полю

## 9. Конфиги, сценарии и тестируемость

- **Конфигурация**:
  - `regularConfig`:
    - частоты выигрышей, частоты спец-символов для горшков
    - вероятность входа в бонус, параметры «бедности/богатости»
  - `bonusConfig`:
    - количество стартовых респинов
    - распределение номиналов монет и мультипликаторов
    - шансы/правила джекпотов
  - `potsConfig`:
    - формулы накопления, лимиты, влияние на бонус
- **Сценарии (`matrix/*.json`)**:
  - Детерминированные сценарии для:
    - серии обычных спинов
    - отдельных бонусных игр
    - edge-кейсов (мгновенный бонус, большие множители, все горшки заполнены и т.п.)
- **Совместимость с архитектурой slot_5**:
  - Переиспользуем:
    - формат событий (`event`, `grid`, `groupMarkup`, `winningGroups`, `payouts`, `totalPayout` + свои поля)
    - идею пошаговой генерации сценария и каскадов
    - паттерны работы со Spine (`SPINE_PIXI_GUIDE.md`)
