Zeus 3 Pots – логика вращения лент и подключение анимации Timing Tool

Документ описывает, как в слоте slot_972_Zeus_3_Pots реализовано вращение рилов по экспортам из Timing Tool (hw_normal_speed.json) и как эти анимации связаны со сценариями игры. Основные файлы: - reel_animation/hw_normal_speed.json – экспорт Timing Tool для режима Hold & Win. - ReelAnimationCurve.js – интерпретация профиля анимации. - ZeusReel.js – логика одной ленты (одной ячейки 3×3). - ZeusSlotManager.js – менеджер сетки 3×3 и связи со сценарием. - zeusMain.js – создание приложения, загрузка профиля, отладочный рил слева.

1. Профиль Timing Tool – hw_normal_speed.json

Профиль соответствует спецификации из slots/timing_tool/export/REEL_ANIMATION_README.md. Для нас важны поля:
  • step – высота одного символа на ленте (px). Вся вертикальная логика рила опирается только на это значение.
  • tapeLength, extraLength – код рассчитывает эффективную длину линейного участка в шагах для каждой колонки: 
    n = tapeLength + col * extraLength
  • containers.start.durationMs, containers.start.rangePx
  • containers.linear.durationMs, containers.linear.distancePx
  • containers.end.durationMs, containers.end.rangePx
  • startCurve, endCurve – Bezier кейфреймы для фаз старта и финиша (overshoot/возврат).
Профиль не знает ничего о сценарии (матрице символов). Он описывает только геометрию движения ленты: сколько времени длится каждая фаза и на сколько пикселей смещается лента.

2. Интерпретация профиля – ReelAnimationCurve

Файл: ReelAnimationCurve.js

2.1. Основные поля и конструктор

При создании:
  • Сохраняется step из профиля (высота символа).
  • Для заданной колонки col вычисляется: 
    n = tapeLength + col * extraLength
    и на его основе:
    • startDuration, linearDuration = linear.durationMs * n, endDuration
    • linearDistance = (linear.distancePx || step) * n
  • Сохраняются массивы ключей startCurve и endCurve.
  • Вычисляются реальные смещения от Bezier-кривых (учитывая overshoot):
    • startOffset = evaluateStartBezier(1) – сколько лента реально проходит за фазу Start.
    • endDelta = evaluateEndBezier(1) - evaluateEndBezier(0) – чистый вклад фазы End.
  • Общее смещение за спин: 
    totalDistance = startOffset + linearDistance + endDelta

2.2. Функция смещения по времени

Метод getOffsetAt(t) реализует кусочную анимацию Start → Linear → End по той же схеме, что и getCubeProgressNoWrap в timing_preview_hold_win.js:
  • Для t раньше старта – возвращает начальное значение (обычно 0).
  • Для фазы Start – интерполирует t по startCurve.
  • Для Linear – даёт линейный рост от конца Start до конца Linear на linearDistance.
  • Для End – добавляет приращение по endCurve относительно начального значения End.
Именно getOffsetAt(t) используется в ZeusReel для вычисления текущего положения ленты.

3. Связь с матрицей сценария – ZeusSlotManager

Файл: ZeusSlotManager.js

3.1. Структура сетки

  • Размер поля: ROWS = 3, COLS = 3.
  • Каждая ячейка сетки 3×3 представлена отдельным объектом ZeusReel (по факту – отдельный маленький рил).
  • Для каждой колонки создаётся свой экземпляр ReelAnimationCurve с учётом tapeLength/extraLength.
Создание рилов:
  • Позиции считаны от originX / originY, вертикальный шаг – rowStep = reelProfile.step || SYMBOL_HEIGHT.
  • Каждому рилу задаётся startDelayMs = reelIndex * curve.reelStartDelayMs (каскадный старт слева-направо, сверху-вниз).

3.2. Сценарий и шаги спина

Менеджер хранит:
  • spinIndex – счётчик спинов / шагов сценария.
Методы:
  • setMatrixImmediately(matrix) – устанавливает матрицу без анимации: каждый ZeusReel получает свой currentSymbol.
  • spinToMatrix(targetMatrix):
    1. Увеличивает spinIndex.
    2. Для каждой ячейки вызывает reel.spinToSymbol(targetSymbol, spinIndex), где:
      • currentSymbol – значение из текущей матрицы (состояние до спина).
      • targetSymbol – значение из новой матрицы (состояние после спина).
Матрица описывает только состояния между спинами: «сейчас» и «после спина». Вращение ленты гарантирует, что уезжающий символ под маской соответствует currentSymbol, а приезжающий — targetSymbol.

4. Логика одной ленты – ZeusReel

Файл: ZeusReel.js

4.1. Опорные индексы на бесконечной ленте

Лента рассматривается как бесконечная последовательность символов, промаркированная целыми индексами k. Для связи с матрицей используются опорные индексы:
  • anchorIndex – индекс символа, который ВИДЕН под маской в начале спина (уезжающий символ).
  • targetAnchorIndex – индекс символа, который окажется под маской в конце спина (приезжающий символ).
  • anchorStepId и targetAnchorStepId – номера шага сценария для уезжающего / приезжающего символа (для отладки). Эти значения добавляются к подписи col,row на самих символах в виде [номер].

4.2. Запуск спина – spinToSymbol(symbolType, stepId)

При старте спина:
  1. Сохраняется targetSymbol = symbolType.
  2. Вычисляется, сколько шагов (по step) пройдёт центр окна: 
    const absDist = Math.abs(totalDistance);
const steps   = Math.max(1, Math.round(absDist / step));
const direction = totalDistance >= 0 ? 1 : -1;
  3. Обновляются опорные индексы: 
    targetAnchorIndex  = anchorIndex + direction * steps;
targetAnchorStepId = stepId;
  4. Важно: никакой «перекраски» ленты не происходит. Символы привязаны к индексам k, а какие именно символы должны быть у опорных индексов — определяется функцией _getSymbolByIndex(k).

4.3. Смещение по времени – связь с Timing Tool

В update(deltaMs) по текущему времени t получается смещение по кривой: 
const offset = curve.getOffsetAt(t);
const direction = totalDistance >= 0 ? 1 : -1;
const effectiveOffset = (offset - curveOffsetStart) * direction;
Далее строится «мировой» прогресс ленты в пикселях: 
// anchorIndex трактуется как символ ПОД маской.
// В превью Timing Tool base = символ НАД маской,
// поэтому base = anchorIndex + 1.
const progressWorld = (anchorIndex + 1) * step + effectiveOffset;
Это соответствует формуле progress в drawHoldWinCell из timing_preview_hold_win.js. Далее: 
const base = Math.floor(progressWorld / step);
const kMin = base - 2;
И для небольшого пула символов (обычно 4): 
for (let i = 0; i < poolSize; i += 1) {
  const k = kMin + i;
  const y = -step + (progressWorld - k * step);
  const visibleY = y + padding;
  const symbolType = _getSymbolByIndex(k);
  ...
}

4.4. Мэппинг индекса в тип символа – _getSymbolByIndex(k)

Лента не хранится как явный массив. Вместо этого есть функция: 
_getSymbolByIndex(k) {
  if (k === anchorIndex)      return currentSymbol; // уезжающий
  if (k === targetAnchorIndex) return targetSymbol; // приезжающий

  // Остальные – детерминированный "рандом" 0/1 по k, row, col.
  const seed = k * 73856093 + col * 19349663 + row * 83492791;
  return (seed & 1) === 0 ? 0 : 1;
}
Таким образом:
  • В начале спина символ под маской (индекс anchorIndex) всегда currentSymbol.
  • В конце спина символ под маской (индекс targetAnchorIndex) всегда targetSymbol.
  • Все промежуточные символы на ленте не меняются в течение спина, так как завязаны на k детерминировано.

4.5. Завершение спина

Когда время спина истекло: 
anchorIndex   = targetAnchorIndex;
anchorStepId  = targetAnchorStepId;
currentSymbol = targetSymbol;
То есть:
  • Приехавший по сценарию символ становится текущим и будет уезжать в следующем спине.
  • Опорная позиция ленты смещается вперёд на steps шагов по профилю Timing Tool.

5. Подключение в zeusMain.js и отладка

Файл: zeusMain.js

5.1. Загрузка профиля

  • Профиль загружается из ./reel_animation/hw_normal_speed.json и без изменений передаётся в ReelAnimationCurve и ZeusSlotManager.
  • При ошибке загрузки используется fallback-профиль, но в реальной игре должен применяться именно экспорт Timing Tool.

5.2. Отладочная лента слева

Для визуальной проверки создан отдельный ZeusReel слева от сетки:
  • Использует тот же профиль и кривую, что и центральная колонка (col = 1).
  • Маска отключена (useMask: false), чтобы видеть всю ленту.
  • При каждом спине ему передаётся тот же stepId и целевой символ, что и ячейке [1,1] сетки.
На отладочной ленте благодаря индексам col,row и [stepId] можно визуально убедиться, что:
  • уезжающий и приезжающий символы на ленте совпадают с состояниями матрицы сценария;
  • во время анимации эти опорные символы не «подкрашиваются» и не перескакивают;
  • ленту ведёт профиль Timing Tool (start / linear / end с overshoot), но логика символов остаётся стабильной.

6. Итог

  • Timing Tool полностью управляет геометрией движения ленты (время, дистанция, кривая).
  • Сценарий управляет только тем, какой символ уезжает и какой приезжает в каждой ячейке.
  • ZeusReel связывает эти два мира через опорные индексы на бесконечной ленте и детерминированный мэппинг k → symbolType.
