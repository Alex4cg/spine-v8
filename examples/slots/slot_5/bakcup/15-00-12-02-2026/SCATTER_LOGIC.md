# Логика скаттеров

Документ описывает логику работы скаттеров в каскадном слоте: типы скаттеров, их генерацию, неуязвимость к бомбам и выигрышным комбинациям, активацию бонусной функции, а также интеграцию с Spine анимациями.

**Важно:** Скаттеры не участвуют в выигрышных комбинациях и не учитываются в выплатах. Они служат исключительно для активации бонусной функции (фриспины) при достижении порога активации (по умолчанию 4+ скаттеров любого цвета).

---

## 1. Скаттеры как символы

### Типы скаттеров

- **Синий скаттер:** `SCATTER_BLUE = 9`
  - Текстура: `+1fs_blue.png`
  - Spine скин: `blue`
  
- **Золотой скаттер:** `SCATTER_GOLD = 10`
  - Текстура: `+1fs_gold.png`
  - Spine скин: `gold`
  
- **Красный скаттер:** `SCATTER_RED = 11`
  - Текстура: `+1fs_red.png`
  - Spine скин: `red`

### Идентификация

- В сетке скаттеры имеют уникальные `symbolType` (9, 10, 11), отличные от обычных символов (0-7) и бомбы (8).
- Скаттеры могут появляться в любом количестве на поле (в отличие от бомбы, где максимум одна за насыпание).
- Все три типа скаттеров считаются вместе для активации бонуса (цвет не имеет значения для активации).

## 2. Генерация скаттеров

### При генерации спина

**Метод:** `generateRandomGrid(allowBomb = true, allowScatter = true)`

- После генерации обычных символов и бомбы (если разрешена) добавляется логика генерации скаттеров.
- Для каждой ячейки сетки с шансом `scatterSpinChance` (по умолчанию 3%) может быть размещён скаттер.
- Тип скаттера выбирается случайно из трёх доступных (9, 10 или 11).
- Можно разместить несколько скаттеров на одном поле (каждый с отдельным шансом).
- Скаттеры могут появляться вместе с бомбой на одном поле.

**Пример:**
```javascript
if (allowScatter && Math.random() < this.scatterSpinChance) {
  const scatterType = this.SCATTER_SYMBOL_TYPES[
    Math.floor(Math.random() * this.SCATTER_SYMBOL_TYPES.length)
  ];
  grid[row][col] = scatterType;
}
```

### При досыпке после спина

**Метод:** `fillEmptySpots(..., isCascadeRefill = false)`

- При досыпке после удаления выигрышных символов (первый каскад после спина).
- Для каждого пустого места с шансом `scatterRefillChance` (по умолчанию 1%) может быть размещён скаттер.
- Тип скаттера выбирается случайно.

### При досыпке внутри каскада

**Метод:** `fillEmptySpots(..., isCascadeRefill = true)`

- При досыпке во время каскада (после второго и последующих удалений выигрышных символов).
- Для каждого пустого места с шансом `scatterCascadeChance` (по умолчанию равен `scatterRefillChance`, можно задать отдельно) может быть размещён скаттер.
- Тип скаттера выбирается случайно.

**Важно:** Скаттеры могут появляться на любом этапе игры: на начальном спине, при досыпке после спина, и при досыпке внутри каскада.

## 3. Неуязвимость скаттеров

### Иммунитет к взрывам бомбы

**Проблема:** При взрыве бомбы уничтожаются 8 соседних символов. Скаттеры не должны быть уничтожены.

**Решение:**

1. **В генераторе сценариев (`ScenarioGeneratorV3`):**
   - При создании события с бомбой типа `explode` в `createGroupMarkup` передаются `explodedPositions` (позиции бомбы и её соседей).
   - Для каждой позиции из `explodedPositions` проверяется, является ли символ скаттером.
   - Если да, в `groupMarkup[row][col]` устанавливается значение `-2` (специальная метка "скаттер под взрывом").
   - Значение `-2` сигнализирует игровой логике, что этот символ не должен быть удалён.

2. **В игровом менеджере (`CascadeManager`):**
   - В методе `_handleBombExplode` при обработке `explodedPositions` проверяется `groupMarkup[row][col]`.
   - Если значение `-2`, символ пропускается (не добавляется в `symbolsToRemove`).
   - Скаттер остаётся на поле после взрыва бомбы.

**Пример кода:**
```javascript
// В createGroupMarkup
if (explodedPositions) {
  for (const pos of explodedPositions) {
    const symbol = grid[pos.row][pos.col];
    if (this.SCATTER_SYMBOL_TYPES.includes(symbol)) {
      groupMarkup[pos.row][pos.col] = -2; // Скаттер под взрывом
    }
  }
}

// В CascadeManager._handleBombExplode
for (const pos of explodedPositions) {
  if (step.groupMarkup && step.groupMarkup[pos.row] && 
      step.groupMarkup[pos.row][pos.col] === -2) {
    continue; // Пропустить скаттер
  }
  symbolsToRemove.push(pos);
}
```

### Иммунитет к выигрышным комбинациям

**Проблема:** Скаттеры не должны удаляться вместе с выигрышными символами.

**Решение:**

1. **В генераторе сценариев:**
   - Метод `findWinningGroups` игнорирует скаттеры при поиске выигрышных групп.
   - Метод `countSymbols` исключает скаттеры из подсчёта символов для выплат.
   - Метод `removeSymbols` проверяет, не является ли символ скаттером перед удалением.

2. **В игровом менеджере:**
   - При удалении выигрышных символов скаттеры автоматически пропускаются (они не входят в `winningGroups`).

**Важно:** Скаттеры остаются на поле до конца каскада и могут накапливаться от шага к шагу.

## 4. Подсчёт и активация скаттеров

### Подсчёт скаттеров

**Метод:** `countScatters(grid)`

Возвращает объект с информацией о скаттерах:
```javascript
{
  total: number,        // Всего скаттеров на поле
  blue: number,         // Синих скаттеров
  gold: number,         // Золотых скаттеров
  red: number,          // Красных скаттеров
  positions: Array<{row, col, type}>  // Позиции всех скаттеров
}
```

**Логика:**
- Проходит по всей сетке и считает символы типов 9, 10, 11.
- Группирует по типам и собирает позиции.

### Активация бонусной функции

**Условие активации:** `scatterCount >= scatterActivationCount` (по умолчанию 4).

**Логика:**
- В конце каждого спина или каскада проверяется общее количество скаттеров всех типов на поле.
- Если количество ≥ `scatterActivationCount`, флаг `scatterActivated: true` добавляется в событие.
- Информация о скаттерах включается во все события (если есть хотя бы один скаттер).

**Важно:** Активация проверяется в конце каждого шага (спин или каскад), но информация о скаттерах добавляется во все события для отслеживания прогресса.

---

## 5. Информация о скаттерах в событиях

### Структура данных в событиях

Информация о скаттерах добавляется во все события (если есть хотя бы один скаттер на поле):

```javascript
{
  event: 'spin',  // или 'spin-win', 'cascade', 'cascade-win', 'spin-bomb' и т.д.
  // ... другие поля события ...
  scatterCount: number,       // Всего скаттеров на поле
  scatterBlue: number,        // Синих скаттеров
  scatterGold: number,        // Золотых скаттеров
  scatterRed: number,         // Красных скаттеров
  scatterActivated: boolean,  // true если scatterCount >= scatterActivationCount (по умолчанию 4)
  scatterPositions: Array<{row, col, type}>  // Опционально, позиции всех скаттеров
}
```

### Где добавляется информация

**Метод:** `createEvent(grid, eventType, winningGroups, bombPosition, bombAlreadyUsed)`

- Вызывается `countScatters(grid)` для получения информации о скаттерах.
- Если `scatterInfo.total > 0`, информация добавляется в событие.
- Флаг `scatterActivated` устанавливается в `true`, если `scatterInfo.total >= this.scatterActivationCount`.

**Важно:** Информация о скаттерах добавляется во все события, а не только в последнее. Это позволяет игровой логике отслеживать прогресс накопления скаттеров.

## 6. Spine анимации скаттеров

### Загрузка Spine ресурсов

**В `index.html`:**
- Загружаются Spine скелет и атлас для скаттеров:
  - `spine/scatter/skeleton.json`
  - `spine/scatter/skeleton.atlas`
- Создаются алиасы: `SCATTER_SPINE_SKELETON_ALIAS` и `SCATTER_SPINE_ATLAS_ALIAS`.
- Алиасы передаются в `CascadeManager`, который устанавливает их в `Symbol` как статические свойства.

### Создание Spine инстансов

**В классе `Symbol`:**
- При создании символа проверяется, является ли он скаттером (`textureIndex === 9 || 10 || 11`).
- Если да, создаётся `scatterSpineInstance` через метод `_createScatterSpineInstance()`.
- Устанавливается правильный скин (`blue`, `gold` или `red`) в зависимости от `textureIndex`.
- Проигрывается анимация `idle` на треке 0.
- Обычный спрайт скрывается (`sprite.visible = false`).

**Метод:** `_createScatterSpineInstance()`
```javascript
_createScatterSpineInstance() {
  if (!Symbol.scatterSpineSkeletonAlias || !Symbol.scatterSpineAtlasAlias) return;
  
  const skeletonData = PIXI.Assets.get(Symbol.scatterSpineSkeletonAlias);
  const atlasData = PIXI.Assets.get(Symbol.scatterSpineAtlasAlias);
  
  this.scatterSpineInstance = new spine.Spine(skeletonData);
  this.scatterSpineInstance.skeleton.setSkinByName(this.scatterType); // 'blue', 'gold', 'red'
  this.scatterSpineInstance.state.setAnimation(0, 'idle', true);
  
  this.cellContainer.addChild(this.scatterSpineInstance);
  this.isShowingSpine = true;
}
```

### Анимации

- **`idle`:** Проигрывается постоянно на треке 0 при создании скаттера (зациклена).
- **`hit`:** Проигрывается один раз на треке 0 после окончания показа выигрышей (заменяет `idle`).
- **`idle_null`:** Проигрывается постоянно на треке 0 после завершения `hit` (зациклена, заменяет `idle`).
- **`bounce`:** Проигрывается на треке 1 при вызове `showSpineAnimation('bounce')` (например, при активации или для визуального эффекта).

**Метод:** `playScatterHitAnimation()`
```javascript
playScatterHitAnimation() {
  if (!this.isScatter || !this.scatterSpineInstance) return;
  
  // Проигрываем hit один раз на треке 0 (заменяя idle)
  const hitEntry = this.scatterSpineInstance.state.setAnimation(0, 'hit', false);
  if (hitEntry) {
    hitEntry.listener = {
      complete: () => {
        // После завершения hit переключаемся на idle_null в цикле
        this.scatterSpineInstance.state.setAnimation(0, 'idle_null', true);
      }
    };
  } else {
    // Если анимация hit не найдена, сразу переключаемся на idle_null
    this.scatterSpineInstance.state.setAnimation(0, 'idle_null', true);
  }
}
```

**Метод:** `showSpineAnimation(animationName)`
```javascript
if (this.isScatter && this.scatterSpineInstance) {
  if (animationName === 'bounce') {
    this.scatterSpineInstance.state.setAnimation(1, 'bounce', false);
  }
}
```

### Последовательность анимаций

1. **При создании:** `idle` проигрывается постоянно на треке 0.
2. **Проигрывание `hit`:** вызывается `playScatterHitAnimation()` в следующих случаях:
   - **Спин без выигрыша:** после завершения спина (когда нет выигрышных комбинаций).
   - **Спин с выигрышем:** после показа выигрышей и досыпания первого каскада (если следующий каскад без выигрыша).
   - **Последний каскад в серии:** после досыпания последнего каскада (когда следующий шаг - спин).
   - Анимация `hit` проигрывается один раз на треке 0 (заменяя `idle`).
   - После завершения `hit` переключается на `idle_null` в цикле (заменяя `idle`).
3. **При активации или визуальных эффектах:** `bounce` проигрывается на треке 1 поверх текущей анимации.

### Обновление и уничтожение

- **`update()`:** Обновляет физику и мировую трансформацию `scatterSpineInstance`.
- **`destroy()`:** Очищает треки, удаляет из контейнера и уничтожает `scatterSpineInstance`.

## 7. Интеграция с игровой логикой

### В генераторе сценариев (`ScenarioGeneratorV3`)

1. **Генерация:**
   - `generateRandomGrid()` генерирует скаттеры на спине.
   - `fillEmptySpots()` генерирует скаттеры при досыпке.

2. **Подсчёт:**
   - `countScatters()` считает скаттеры на поле.
   - `findScatterPositions()` возвращает множество позиций скаттеров.

3. **Защита от удаления:**
   - `createGroupMarkup()` помечает скаттеры под взрывом значением `-2`.
   - `removeSymbols()` пропускает скаттеры при удалении.

4. **События:**
   - `createEvent()` добавляет информацию о скаттерах во все события.

### В игровом менеджере (`CascadeManager`)

1. **Обработка взрыва бомбы:**
   - `_handleBombExplode()` проверяет `groupMarkup[row][col] === -2` и пропускает скаттеры.

2. **Удаление выигрышных символов:**
   - Скаттеры автоматически не включаются в `winningGroups`, поэтому не удаляются.

3. **Отображение:**
   - Класс `Symbol` создаёт Spine инстансы для скаттеров и управляет их анимациями.

4. **Анимация hit для скаттеров:**
   - Вызывается `_playScatterHitAnimations()` в методе `_onAllLanded()` после проверки выигрыша.
   - Анимация проигрывается в следующих случаях:
     - **Спин без выигрыша:** когда текущий шаг - `spin` и нет выигрышных комбинаций.
     - **Спин с выигрышем:** когда текущий шаг - `cascade` (первый каскад после `spin-win`) и следующий шаг - `cascade` без выигрыша (после досыпания).
     - **Последний каскад:** когда текущий шаг - `cascade` без выигрыша и следующий шаг - `spin` (конец серии каскадов).
   - Метод находит все скаттеры на поле и вызывает для каждого `playScatterHitAnimation()`.
   - Каждый скаттер проигрывает `hit` один раз, затем переключается на `idle_null` в цикле.

### Проверка активации бонуса

**В игровой логике:**
- Проверяется флаг `scatterActivated` в событиях.
- Если `scatterActivated === true`, активируется бонусная функция (фриспины).
- Информация о скаттерах (`scatterCount`, `scatterBlue`, `scatterGold`, `scatterRed`) может использоваться для визуализации прогресса.

## 8. Конфигурация

### Параметры генератора

```javascript
{
  scatterSpinChance: 0.03,        // 3% шанс появления скаттера на спине
  scatterRefillChance: 0.01,       // 1% шанс при досыпке после спина
  scatterCascadeChance: 0.01,     // 1% шанс при досыпке внутри каскада
  scatterActivationCount: 4        // Порог активации (4+ скаттеров)
}
```

### Константы

```javascript
SCATTER_BLUE = 9
SCATTER_GOLD = 10
SCATTER_RED = 11
SCATTER_SYMBOL_TYPES = [9, 10, 11]
```

## 9. Важные детали реализации

### Порядок обработки

1. **Генерация сетки:** сначала обычные символы, затем бомба (если есть), затем скаттеры.
2. **Поиск выигрышей:** скаттеры игнорируются.
3. **Взрыв бомбы:** скаттеры помечаются в `groupMarkup` значением `-2` и не удаляются.
4. **Удаление выигрышных:** скаттеры не включаются в `winningGroups` и не удаляются.
5. **Подсчёт скаттеров:** выполняется для каждого события.
6. **Активация:** проверяется в конце каждого шага.

### Особенности

- **Накопление:** скаттеры накапливаются от шага к шагу и остаются на поле до конца каскада.
- **Цвет не важен:** для активации бонуса учитывается общее количество скаттеров всех типов.
- **Неуязвимость:** скаттеры защищены от удаления как при взрыве бомбы, так и при удалении выигрышных символов.
- **Визуализация:** скаттеры отображаются через Spine анимации с соответствующими скинами.

## 10. Резюме логики

### Генерация
- Скаттеры могут появляться на спине (3%), при досыпке после спина (1%), и при досыпке внутри каскада (1%).
- Тип скаттера выбирается случайно из трёх доступных (синий, золотой, красный).

### Неуязвимость
- Скаттеры не удаляются при взрыве бомбы (помечаются в `groupMarkup` значением `-2`).
- Скаттеры не удаляются вместе с выигрышными символами (не участвуют в выигрышных группах).

### Активация
- В конце каждого шага проверяется общее количество скаттеров.
- Если количество ≥ 4, флаг `scatterActivated: true` добавляется в событие.
- Игровая логика может использовать этот флаг для активации бонуса (фриспины).

### Визуализация
- Скаттеры отображаются через Spine анимации с соответствующими скинами (`blue`, `gold`, `red`).
- При создании проигрывается анимация `idle` постоянно.
- Анимация `hit` проигрывается один раз в следующих случаях:
  - После спина без выигрыша.
  - После спина с выигрышем (после показа выигрышей и досыпания первого каскада, если следующий каскад без выигрыша).
  - В конце последнего каскада в серии (после досыпания).
- После завершения `hit` переключение на `idle_null` в цикле.
- Анимация `bounce` может использоваться для визуальных эффектов (проигрывается на треке 1 поверх текущей анимации).

---

При реализации убедитесь, что:
1. Скаттеры правильно генерируются на всех этапах игры.
2. Скаттеры защищены от удаления при взрыве бомбы (значение `-2` в `groupMarkup`).
3. Скаттеры не участвуют в выигрышных группах и не учитываются в выплатах.
4. Информация о скаттерах добавляется во все события для отслеживания прогресса.
5. Spine анимации правильно создаются и обновляются для каждого типа скаттера.
