# Логика бомбы

Документ описывает логику работы бомбы в каскадном слоте: два режима работы (мультипликатор выигрыша или взрыв), обработка в генераторе сценариев (ScenarioGenerator).

---

## 1. Бомба как символ

- **Тип символа:** бомба — отдельный тип символа (например, `symbolType = 8` или специальный ID, отличный от обычных символов 0-7).
- **Текстура:** `bomb_regular.png` (путь: `slots/slot_5/sym_st/bomb_regular.png`).
- **Ограничение:** максимум **одна бомба** может выпасть за одно насыпание (спин или досыпание в каскаде).
- **Идентификация:** в сетке бомба имеет свой уникальный `symbolType`, отличный от обычных символов.

---

## 2. Два режима работы бомбы

### Режим A: Есть выигрышная комбинация + бомба

**Условие:** на поле есть выигрышные группы (7+ одинаковых символов) **И** есть бомба.

**Действие:**
- Бомба применяет **мультипликатор x5** ко **всем** выигрышам текущего шага.
- Бомба **исчезает** вместе с выигрышными символами (удаляется при обработке выигрыша).

**Последовательность:**
1. Проверка выигрышей → найдены выигрышные группы.
2. Проверка наличия бомбы на поле.
3. Если бомба есть → все выплаты (`totalPayout`) умножаются на 5.
4. Бомба добавляется к списку символов для удаления (вместе с выигрышными).
5. Удаление выигрышных символов + бомбы → каскад (уплотнение → досыпание → проверка).

**В сценарии:** событие `bomb` добавляется **перед** удалением выигрышных символов.

---

### Режим B: Нет выигрышной комбинации + бомба

**Условие:** на поле **нет** выигрышных групп (7+ одинаковых символов), **НО** есть бомба.

**Действие:**
- Бомба **взрывается** и уничтожает **8 соседних символов** (включая диагонали):
  - Верх (`row-1, col`)
  - Низ (`row+1, col`)
  - Лево (`row, col-1`)
  - Право (`row, col+1`)
  - Верх-лево (`row-1, col-1`)
  - Верх-право (`row-1, col+1`)
  - Низ-лево (`row+1, col-1`)
  - Низ-право (`row+1, col+1`)
- Бомба сама **исчезает** при взрыве.
- Если бомба на краю поля, уничтожаются только существующие соседи (проверка границ).

**Последовательность:**
1. Проверка выигрышей → выигрышей нет.
2. Проверка наличия бомбы на поле.
3. Если бомба есть → взрыв:
   - Найти позицию бомбы `(row, col)`.
   - Найти все 8 соседних позиций (с проверкой границ).
   - Пометить бомбу и соседей как удалённые (`-1`).
4. Каскад: уплотнение колонок → заполнение пустых мест → проверка выигрыша.

**В сценарии:** событие `bomb` добавляется **вместо** события `spin` или `cascade` (если нет выигрыша).

---

## 3. Обработка в ScenarioGenerator

### Определение наличия бомбы

После генерации сетки (спин или досыпание):
- Проверить, есть ли в сетке символ с типом бомбы.
- Если есть — запомнить позицию `(row, col)` и флаг наличия бомбы.

### Режим A: Бомба + выигрыш

**В `generateSpinWithCascades()` или `stepCascade()`:**

1. После `findWinningGroups(grid)`:
   - Если `winningGroups.length > 0` **И** есть бомба:
     - Умножить `totalPayout` на 5.
     - Добавить событие `bomb` в шаг сценария:
       ```javascript
       {
         event: 'bomb',
         bombType: 'multiplier',  // или 'explode'
         bombPosition: { row, col },
         multiplier: 5,
         grid: [...],              // сетка до удаления
         winningGroups: [...],     // выигрышные группы
         groupMarkup: [...],
         payouts: [...],           // выплаты ДО умножения
         totalPayout: totalPayout * 5  // выплаты ПОСЛЕ умножения
       }
       ```
     - Бомба добавляется к `winningPositions` для удаления вместе с выигрышными символами.

2. Далее обычная логика: удаление → уплотнение → заполнение → проверка.

### Режим B: Бомба без выигрыша

**В `generateSpinWithCascades()` или `stepCascade()`:**

1. После `findWinningGroups(grid)`:
   - Если `winningGroups.length === 0` **И** есть бомба:
     - Найти позицию бомбы `(row, col)`.
     - Найти все 8 соседних позиций (с проверкой границ поля).
     - Создать `Set` позиций для удаления: бомба + все соседи.
     - Добавить событие `bomb`:
       ```javascript
       {
         event: 'bomb',
         bombType: 'explode',
         bombPosition: { row, col },
         explodedPositions: [{row, col}, ...],  // бомба + соседи
         grid: [...],              // сетка до взрыва
         winningGroups: [],        // выигрышей нет
         groupMarkup: [...],       // все нули
         payouts: [],
         totalPayout: 0
       }
       ```

2. Удалить бомбу и соседей (пометить как `-1`).

3. Далее обычная логика каскада: уплотнение → заполнение → проверка выигрыша.

---

## 4. Генерация бомбы

### При генерации спина

В `generateRandomGrid()` или в функции `getSpinGrid`:
- С вероятностью (например, 5-10%) один из символов заменяется на бомбу.
- Проверка: если бомба уже есть на поле, не генерировать новую.

### При досыпании в каскаде

В функции `getRefillSymbol(cascadeStepIndex, refillIndex)`:
- С вероятностью (например, 3-5%) возвращается бомба вместо обычного символа.
- Проверка: если бомба уже есть на поле после уплотнения, не генерировать новую.

**Важно:** максимум одна бомба за одно насыпание (спин или одно досыпание в каскаде).

---

## 5. Структура события `bomb` в сценарии

```javascript
{
  event: 'bomb',
  bombType: 'multiplier' | 'explode',
  bombPosition: { row: number, col: number },
  
  // Для режима A (multiplier):
  multiplier: 5,              // только если bombType === 'multiplier'
  winningGroups: [...],        // выигрышные группы
  groupMarkup: [...],
  payouts: [...],              // выплаты ДО умножения
  totalPayout: number,         // выплаты ПОСЛЕ умножения (payouts * 5)
  
  // Для режима B (explode):
  explodedPositions: [         // только если bombType === 'explode'
    { row: number, col: number },
    ...
  ],
  
  // Общее:
  grid: number[][],            // сетка до обработки бомбы
  winningGroups: [] | [...],   // пусто для explode, заполнено для multiplier
  groupMarkup: number[][]
}
```

## 6. Последовательность обработки в ScenarioGenerator

### В `generateSpinWithCascades()`:

1. Генерация начального спина → проверка наличия бомбы.
2. Поиск выигрышных групп → `findWinningGroups(spinGrid)`.
3. **Если есть выигрыш И есть бомба:**
   - Создать шаг `bomb` с `bombType: 'multiplier'`.
   - Умножить выплаты на 5.
   - Добавить бомбу к `winningPositions` для удаления.
   - Продолжить обычную логику удаления → каскад.
4. **Если нет выигрыша И есть бомба:**
   - Создать шаг `bomb` с `bombType: 'explode'`.
   - Найти соседей бомбы (8 позиций).
   - Удалить бомбу и соседей → каскад.

### В `stepCascade()`:

Аналогично: после проверки выигрыша на сетке после досыпания проверять наличие бомбы и обрабатывать по режиму A или B.

---

## 7. Интеграция с существующей логикой

- **Удаление символов:** бомба удаляется вместе с выигрышными (режим A) или вместе с соседями (режим B), затем применяется обычная логика `removeWinningSymbols()` → `compactColumns()` → `fillEmptySpots()`.
- **Проверка выигрыша:** после взрыва бомбы (режим B) проверяется новая сетка на наличие выигрышей обычным способом.
- **Каскад:** логика каскада не меняется — уплотнение, досыпание, проверка выигрыша работают как обычно.

---

## 8. Важные детали

- **Максимум одна бомба:** при генерации проверять, не выпала ли уже бомба в текущем насыпании.
- **Проверка границ:** при взрыве проверять, что соседние позиции существуют (`row >= 0`, `row < GRID_ROWS`, `col >= 0`, `col < GRID_COLS`).
- **Событие `bomb`:** всегда добавляется как отдельный шаг в сценарий.
- **Мультипликатор:** применяется ко **всем** выигрышам текущего шага, не только к группам рядом с бомбой.

---

При реализации в `ScenarioGenerator` убедитесь, что:
1. Корректно определяется наличие бомбы на поле.
2. Создаётся событие `bomb` с правильным `bombType` и данными.
3. Бомба корректно добавляется к удаляемым символам (режим A) или к взорванным позициям (режим B).
4. Логика каскада после обработки бомбы работает как обычно (уплотнение → досыпание → проверка).
