# Логика генерации сценариев (ScenarioGenerator)

Документ описывает **чистую логику** генерации спинов и каскадов без анимации. `ScenarioGenerator` создаёт последовательность шагов сценария (spin, spin-win, cascade, cascade-win) с полной информацией о сетке, выигрышных группах, разметке и выплатах.

---

## 1. Формат данных

### Сетка
- **Формат:** `grid[row][col]` — двумерный массив, где `row` от 0 до 4 (сверху вниз), `col` от 0 до 5 (слева направо).
- **Значения:** `0` до `symbolCount-1` (типы символов), `-1` означает пустую ячейку (после удаления выигрышных).
- **Примечание:** В `CascadeManager` используется формат `grid[col][row]`; при загрузке сценария происходит конвертация.

### Выигрышные группы
- **Минимум для выигрыша:** `minSymbolsForWin` (по умолчанию 7).
- **Группа:** все символы одного типа, если их количество ≥ 7.
- **Структура группы:**
  ```javascript
  {
    symbolType: 0-7,        // Тип символа
    count: 7+,              // Количество таких символов на поле
    groupId: 1, 2, 3...,    // Уникальный ID группы (для разметки)
    symbolName: 'h1_diamond' // Имя символа для выплат
  }
  ```

### Разметка групп (groupMarkup)
- **Формат:** `groupMarkup[row][col]` — двумерный массив той же размерности, что и сетка.
- **Значения:** `0` = символ не выигрышный, `1+` = номер группы выигрышных символов.
- **Назначение:** позволяет найти все позиции конкретной группы выигрышных символов (например, все символы группы 1).

---

## 2. Генерация случайного поля (спин)

**Метод:** `generateRandomGrid()`

- Для каждой ячейки `grid[row][col]` генерируется случайное число от `0` до `symbolCount-1`.
- Никаких гарантий отсутствия выигрышей — поле полностью случайное.
- Возвращает новую сетку `[row][col]`.

**Пример:**
```javascript
// Сетка 5x6, 8 типов символов (0-7)
[
  [0, 1, 2, 3, 4, 5],
  [6, 7, 0, 1, 2, 3],
  [4, 5, 6, 7, 0, 1],
  [2, 3, 4, 5, 6, 7],
  [0, 1, 2, 3, 4, 5]
]
```

---

## 3. Поиск выигрышных групп

**Метод:** `findWinningGroups(grid)`

**Алгоритм:**

1. **Подсчёт символов:** `countSymbols(grid)` проходит по всей сетке и считает количество каждого типа символа. Возвращает `Map<symbolType, count>`.

2. **Фильтрация:** для каждого типа символа, если `count >= minSymbolsForWin` (7+), создаётся группа с уникальным `groupId` (1, 2, 3...).

3. **Сортировка:** группы сортируются по `symbolType` (для стабильности порядка).

**Важно:** Группа включает **все** символы данного типа на поле, даже если они не соседствуют. Например, если на поле 8 символов типа "0", все они попадают в одну группу с `count: 8`, независимо от их расположения.

**Пример:**
```javascript
// Сетка с 8 символами типа 0 и 7 символами типа 1
winningGroups = [
  { symbolType: 0, count: 8, groupId: 1, symbolName: 'h1_diamond' },
  { symbolType: 1, count: 7, groupId: 2, symbolName: 'h2_gold' }
]
```

---

## 4. Создание разметки групп

**Метод:** `createGroupMarkup(grid, winningGroups)`

**Алгоритм:**

1. Создаётся маппинг `symbolType → groupId` из `winningGroups`.
2. Для каждой ячейки `grid[row][col]`:
   - если символ входит в выигрышную группу → `markup[row][col] = groupId`;
   - иначе → `markup[row][col] = 0`.

**Результат:** разметка позволяет быстро найти все позиции конкретной группы. Например, чтобы найти все символы группы 1, достаточно пройти по `groupMarkup` и собрать позиции, где значение равно 1.

**Пример:**
```javascript
// Сетка:
grid = [
  [0, 1, 2, ...],
  [0, 1, 3, ...],
  ...
]

// Разметка (если символы 0 и 1 выигрышные, groupId 1 и 2):
groupMarkup = [
  [1, 2, 0, ...],  // символ 0 → группа 1, символ 1 → группа 2
  [1, 2, 0, ...],
  ...
]
```

---

## 5. Удаление выигрышных символов

**Метод:** `removeWinningSymbols(grid, winningPositions)`

**Алгоритм:**

1. `findWinningPositions(grid)` находит все позиции выигрышных символов (7+ одинаковых):
   - подсчитывает количество каждого типа символа;
   - для каждого символа, если его тип встречается ≥ 7 раз, позиция добавляется в `Set` строк вида `"row,col"`.

2. Создаётся новая сетка: для каждой позиции из `winningPositions` ставится `-1` (пусто), остальные символы копируются как есть.

**Результат:** сетка с пустыми ячейками (`-1`) на месте удалённых выигрышных символов.

---

## 6. Уплотнение колонок (гравитация)

**Метод:** `compactColumns(grid)`  
**Логика совпадает с `CascadeManager.compactColumns()`**

**Алгоритм:**

Для каждой колонки `col`:

1. **Сбор символов снизу вверх:** проходим от `row = GRID_ROWS-1` до `row = 0`, собираем все непустые символы (`>= 0`) в массив `symbolsInColumn`.

2. **Размещение снизу вверх:** размещаем собранные символы обратно в колонку, начиная с нижнего ряда:
   - `newRow = GRID_ROWS - 1 - i` (где `i` — индекс в массиве символов);
   - первый символ → `row = 4`, второй → `row = 3`, и т.д.

3. **Пустые места сверху:** все ряды выше заполненных помечаются как `-1` и добавляются в `emptySpots`.

**Результат:** `{ grid: compacted, emptySpots: [{row, col}, ...] }`

**Пример:**
```javascript
// До уплотнения (колонка 0):
[0, -1, 1, -1, 2]  // row 0-4

// После уплотнения:
[-1, -1, 0, 1, 2]  // символы "упали" вниз, пустоты сверху
// emptySpots: [{row: 0, col: 0}, {row: 1, col: 0}]
```

---

## 7. Заполнение пустых мест

**Метод:** `fillEmptySpots(grid, emptySpots, getNextSymbol)`

**Алгоритм:**

1. **Сортировка:** `emptySpots` сортируются сначала по колонке (`col`), затем по ряду (`row`). Порядок заполнения: колонка 0, ряды 0→4; колонка 1, ряды 0→4; ... колонка 5, ряды 0→4.

2. **Заполнение:** для каждого пустого места вызывается `getNextSymbol(index)`, где `index` — порядковый номер пустого места (0, 1, 2...). Результат записывается в сетку.

**Параметры `getNextSymbol`:**
- `getNextSymbol(cascadeStepIndex, refillIndex)` — функция, которая возвращает следующий символ для досыпания.
  - `cascadeStepIndex` — номер шага каскада (0 для первого каскада после спина, 1 для второго, ...);
  - `refillIndex` — порядковый номер пустого места в текущем шаге каскада.

**Результат:** сетка с заполненными пустотами.

---

## 8. Один шаг каскада

**Метод:** `stepCascade(grid, getNextSymbol)`

**Последовательность:**

1. **Поиск выигрышей:** `findWinningPositions(grid)` — если выигрышей нет, возвращается `{ grid: копия сетки, hasWin: false }`.

2. **Удаление:** `removeWinningSymbols(grid, winningPositions)` — выигрышные символы помечаются как `-1`.

3. **Уплотнение:** `compactColumns(afterRemove)` — символы падают вниз, возвращается `{ grid: compacted, emptySpots }`.

4. **Заполнение:** `fillEmptySpots(compacted, emptySpots, getNextSymbol)` — пустые места заполняются новыми символами.

5. **Проверка нового выигрыша:** `findWinningPositions(filled)` — если есть новые выигрыши, `hasWin = true`.

**Результат:** `{ grid: заполненная сетка, hasWin: boolean }`

---

## 9. Генерация спина с каскадами

**Метод:** `generateSpinWithCascades(getSpinGrid, getRefillSymbol)`

**Последовательность:**

### Шаг 1: Генерация начального спина

1. Вызывается `getSpinGrid()` — генерируется начальное поле спина.
2. Находятся выигрышные группы: `findWinningGroups(spinGrid)`.
3. Создаётся разметка: `createGroupMarkup(spinGrid, winningGroups)`.
4. Рассчитываются выплаты: `calculatePayouts(winningGroups)`.
5. Определяется тип события:
   - если есть выигрыш → `event: 'spin-win'`;
   - иначе → `event: 'spin'`.
6. Создаётся первый шаг сценария:
   ```javascript
   {
     event: 'spin' | 'spin-win',
     grid: [...],           // копия сетки
     winningGroups: [...],  // копия групп
     groupMarkup: [...],    // копия разметки
     payouts: [...],        // выплаты
     totalPayout: number    // общая выплата
   }
   ```

### Шаг 2: Обработка каскадов (если был выигрыш)

Если `winningGroups.length === 0`, серия завершена, возвращается массив с одним шагом (spin).

Иначе запускается цикл `while (true)`:

1. Вызывается `stepCascade(currentGrid, getNextSymbol)`:
   - удаление → уплотнение → заполнение → проверка нового выигрыша.

2. Определяются группы и выплаты для каскада:
   - `findWinningGroups(nextGrid)`;
   - `createGroupMarkup(nextGrid, cascadeWinningGroups)`;
   - `calculatePayouts(cascadeWinningGroups)`.

3. Определяется тип события каскада:
   - если есть выигрыш → `event: 'cascade-win'`;
   - иначе → `event: 'cascade'`.

4. Создаётся шаг каскада:
   ```javascript
   {
     event: 'cascade' | 'cascade-win',
     grid: [...],
     winningGroups: [...],
     groupMarkup: [...],
     payouts: [...],
     totalPayout: number
   }
   ```

5. Если `cascadeWinningGroups.length === 0` → выход из цикла (серия завершена).

6. Иначе `currentGrid = nextGrid`, `cascadeStepIndex++`, цикл продолжается.

**Результат:** массив шагов сценария. Пример последовательности:
- `spin-win` → `cascade-win` → `cascade-win` → `cascade` (завершение)

---

## 10. Типы событий и их значения

| Событие | Значение |
|---------|----------|
| `spin` | Спин без выигрыша. Серия завершена. |
| `spin-win` | Спин с выигрышем. Обязательно за ним следует `cascade` или `cascade-win`. |
| `cascade` | Каскад без выигрыша. Серия завершена. |
| `cascade-win` | Каскад с выигрышем. Обязательно за ним следует `cascade` или `cascade-win`. |

**Правила:**
- `spin` или `cascade` без `-win` всегда завершают серию.
- `spin-win` или `cascade-win` всегда имеют следующий шаг (каскад).
- После `spin-win` всегда идёт каскад (даже если он без выигрыша).

---

## 11. Генерация полного сценария

**Метод:** `generateScenario(spinCount)`

**Алгоритм:**

1. Сброс: `reset()` — очистка сетки и сценария.

2. Цикл по количеству спинов:
   - для каждого спина вызывается `generateSpinWithCascades()`:
     - `getSpinGrid = () => this.generateRandomGrid()` — случайное поле;
     - `getRefillSymbol = (cascadeStepIndex, refillIndex) => Math.floor(Math.random() * this.symbolCount)` — случайный символ для досыпания.
   - все шаги добавляются в общий сценарий.

3. Возвращается полный массив шагов.

**Результат:** массив шагов, где каждый спин может породить несколько шагов (spin-win + каскады).

**Пример сценария из 2 спинов:**
```javascript
[
  { event: 'spin-win', ... },      // спин 1: есть выигрыш
  { event: 'cascade-win', ... },   // каскад 1: есть выигрыш
  { event: 'cascade', ... },       // каскад 2: нет выигрыша, завершение
  { event: 'spin', ... }           // спин 2: нет выигрыша, завершение
]
```

---

## 12. Расчёт выплат

**Метод:** `calculatePayouts(winningGroups)`

**Алгоритм:**

1. Для каждой группы из `winningGroups`:
   - берётся `count` (количество символов) и `symbolName`;
   - из `payoutsConfig.payouts[count][symbolName]` берётся выплата;
   - если выплата найдена, добавляется в массив `payouts` с информацией о группе.

2. Суммируется `totalPayout` из всех выплат.

**Структура `payoutsConfig`:**
```javascript
{
  payouts: {
    "7": { "h1_diamond": 10, "h2_gold": 8, ... },
    "8": { "h1_diamond": 20, "h2_gold": 15, ... },
    ...
  }
}
```

**Результат:** `{ payouts: [...], totalPayout: number }`

## 13. Важные детали реализации

### Порядок заполнения пустых мест
- Сначала по колонке (0→5), затем по ряду (0→4).
- Это соответствует порядку падения символов в анимации: колонка 0 падает первой, затем колонка 1, и т.д.

### Уплотнение колонок
- Логика идентична `CascadeManager.compactColumns()`: символы собираются снизу вверх и размещаются снизу вверх.
- Это гарантирует, что сгенерированный сценарий точно соответствует тому, что произойдёт в анимации.

### Выигрышные группы
- Группа включает **все** символы одного типа на поле (7+), даже если они не соседствуют.
- Это отличается от "кластеров" (соседние символы) — здесь просто подсчёт по типу.

### Формат сетки
- `ScenarioGenerator` использует `grid[row][col]` для удобства записи (строка = один горизонтальный ряд).
- `CascadeManager` использует `grid[col][row]` для удобства работы с колонками.
- При загрузке сценария происходит конвертация формата.

---

## 14. Использование сценария в CascadeManager

При загрузке сценария:

1. **Конвертация формата:** `grid[row][col]` → `grid[col][row]`.
2. **Загрузка шагов:** каждый шаг содержит `grid`, `winningGroups`, `groupMarkup`.
3. **Продвижение по шагам:** `CascadeManager` использует `currentScenarioStep` для определения текущего шага.
4. **Получение символов:** `getNextScenarioSymbol(col, row, context)` возвращает символ из текущего шага сценария вместо случайного.

**Важно:** Сценарий предопределяет **все** символы, которые появятся на поле (и в спине, и в каскадах). Это позволяет воспроизвести точную последовательность событий для тестирования или демонстрации.

---

При изменении логики генерации обновите этот документ и убедитесь, что изменения синхронизированы с `CascadeManager` (особенно `compactColumns` и порядок заполнения).
