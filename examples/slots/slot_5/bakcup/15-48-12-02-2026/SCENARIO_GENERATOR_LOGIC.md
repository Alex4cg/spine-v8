# Логика генерации сценариев (ScenarioGeneratorV3)

Документ описывает **логику генератора сценариев** (ScenarioGeneratorV3). Генератор работает пошагово: **насыпал → сохранил → нашёл выигрыши/бомбы → записал → досыпал → сохранил**. Создаётся последовательность шагов с полной информацией о сетке, выигрышных группах, разметке и выплатах. Включает логику работы бомбы.

---

## 0. Типы событий в сценарии

### Полный список событий

| Событие | Описание | Что происходит с матрицей |
|---------|----------|---------------------------|
| `spin` | Спин без выигрыша и без бомбы | Матрица не меняется, серия завершена |
| `spin-win` | Спин с выигрышем и без бомбы | Удаление выигрышных → уплотнение → досыпание → каскад |
| `spin-win-bomb` | Спин с выигрышем и с бомбой | Мультипликатор x5 к выплатам. Удаление выигрышных **и бомбы** → уплотнение → досыпание → каскад |
| `spin-bomb` | Спин с бомбой без выигрыша | Сетка ДО взрыва. Взрыв бомбы + 8 соседей → уплотнение → досыпание → событие `cascade`/`cascade-win` |
| `cascade` | Каскад без выигрыша | Матрица не меняется, серия завершена |
| `cascade-win` | Каскад с выигрышем | Удаление выигрышных → уплотнение → досыпание → проверка |
| `cascade-win-bomb` | Каскад с выигрышем и с бомбой | Мультипликатор x5 к выплатам. Удаление выигрышных **и бомбы** → уплотнение → досыпание → проверка |
| `cascade-bomb` | Каскад с бомбой без выигрыша | Сетка ДО взрыва. Взрыв бомбы + 8 соседей → уплотнение → досыпание → событие `cascade`/`cascade-win` |

### Логика событий с бомбой

**Если есть выигрыш + бомба:**
- Создаётся событие `spin-win-bomb` или `cascade-win-bomb` (не отдельное `bomb`).
- Бомба применяет мультипликатор x5 к выплатам.
- Бомба **удаляется вместе с выигрышными символами** (одним шагом).
- Матрица меняется из-за удаления выигрышных символов и бомбы.

**Если нет выигрыша + бомба:**
- Создаётся событие `spin-bomb` или `cascade-bomb` (сетка ДО взрыва).
- Событие содержит `bombPosition`, `explodedPositions`, `bombType: 'explode'`.
- После обработки взрыва создаётся событие `cascade` или `cascade-win` (сетка ПОСЛЕ взрыва и досыпания).
- CascadeManager обрабатывает взрыв, затем переходит к следующему шагу.

### Правила последовательности событий

- `spin` или `cascade` без `-win` всегда завершают серию.
- `spin-win` / `cascade-win` всегда имеют следующий шаг (каскад).
- `spin-win-bomb` / `cascade-win-bomb` всегда имеют следующий шаг (каскад).
- `spin-bomb` / `cascade-bomb` всегда имеют следующий шаг (`cascade` или `cascade-win` — состояние ПОСЛЕ взрыва).

## 1. Формат данных

### Сетка
- **Формат:** `grid[row][col]` — двумерный массив: `row` 0…4 (сверху вниз), `col` 0…5 (слева направо).
- **Значения:** `0`…`symbolCount-1` (типы символов), `8` (`BOMB_SYMBOL_TYPE`) — бомба, `9` (`SCATTER_BLUE`) — синий скаттер, `10` (`SCATTER_GOLD`) — золотой скаттер, `11` (`SCATTER_RED`) — красный скаттер, `-1` — пустая ячейка (после удаления).
- **Примечание:** В CascadeManager используется `grid[col][row]`; при загрузке сценария выполняется конвертация.

### Бомба
- **Тип символа:** `BOMB_SYMBOL_TYPE = 8` (отдельно от обычных 0–7).
- **Ограничение:** максимум **одна бомба** за одно насыпание (спин или досыпание).
- **Идентификация:** в сетке бомба — отдельный `symbolType`.

### Выигрышные группы
- **Минимум для выигрыша:** `minSymbolsForWin` (по умолчанию 7).
- **Группа:** все символы одного типа с количеством ≥ 7.
- **Структура группы:**
  ```javascript
  {
    symbolType: 0-7,
    count: 7+,
    groupId: 1, 2, 3...,
    symbolName: 'h1_lion'  // имя из symbolNames / payouts
  }
  ```

### Разметка групп (groupMarkup)
- **Формат:** `groupMarkup[row][col]`, размерность как у сетки.
- **Значения:** `0` — не выигрышный, `1+` — номер группы выигрышных символов, `-2` — скаттер под взрывом (не удалять).
- **Назначение:** по разметке находятся все позиции каждой выигрышной группы. Значение `-2` используется для пометки скаттеров, попавших под взрыв бомбы, чтобы игра знала их не удалять.

### Скаттеры
- **Типы символов:** `SCATTER_BLUE = 9`, `SCATTER_GOLD = 10`, `SCATTER_RED = 11`.
- **Шансы появления:**
  - На спине: `scatterSpinChance` (по умолчанию 3%).
  - При досыпке после спина: `scatterRefillChance` (по умолчанию 1%).
  - При досыпке внутри каскада: `scatterCascadeChance` (по умолчанию равен `scatterRefillChance`, можно задать отдельно).
- **Неуязвимость:** скаттеры НЕ удаляются при взрыве бомбы и НЕ удаляются вместе с выигрышными символами. Остаются на поле до конца каскада.
- **Активация:** в конце каждого каскада проверяется общее количество скаттеров всех типов. Если `total >= scatterActivationCount` (по умолчанию 4), информация об активации (флаг `scatterActivated: true`) добавляется в последнее событие спина или каскада.
- **Подсчёт:** скаттеры не участвуют в выигрышных группах (`findWinningGroups` их игнорирует) и не учитываются в `countSymbols` для выплат.

## 2. Пошаговая логика генератора

Общий принцип: **насыпал → сохранил матрицу → нашёл выигрыши и бомбы → записал позиции и результаты → досыпал → сохранил**.

### Шаг 1: Генерация поля (спин)

**Метод:** `generateRandomGrid(allowBomb = true, allowScatter = true)`

**Последовательность генерации:**

1. **Обычные символы:** для каждой ячейки `grid[row][col]` — случайное число от `0` до `symbolCount-1`.
2. **Бомба:** с вероятностью `bombSpinChance` (3%) одна случайная ячейка заменяется на бомбу (`8`). Максимум одна бомба за спин.
3. **Скаттеры:** после размещения бомбы, для каждой ячейки (кроме ячейки с бомбой) с вероятностью `scatterSpinChance` (3%) обычный символ заменяется на скаттер случайного типа (`9`, `10` или `11`). Можно разместить несколько скаттеров на одном поле (каждый с отдельным шансом). Скаттеры могут появляться вместе с бомбой на одном поле.

**Важно:** Скаттеры заменяют обычные символы, но не могут заменить бомбу (ячейка с бомбой пропускается при генерации скаттеров).

- Возвращает сетку `[row][col]`.

### Шаг 2: Подсчёт символов

**Метод:** `countSymbols(grid)`

- Обход всей сетки, подсчёт количества каждого типа символа.
- Бомба (`BOMB_SYMBOL_TYPE`) и скаттеры (`SCATTER_SYMBOL_TYPES = [9, 10, 11]`) **не учитываются**.
- Возвращает `Map<symbolType, count>`.

### Шаг 3: Поиск выигрышных групп

**Метод:** `findWinningGroups(grid)`

- Использует `countSymbols(grid)`.
- Для каждого типа с `count >= minSymbolsForWin` создаётся группа с уникальным `groupId` и `symbolName` из `symbolNames[symbolType]`.
- Группы сортируются по `symbolType`.
- Группа — **все** символы данного типа на поле (7+), бомба не участвует.

### Шаг 4: Разметка групп

**Метод:** `createGroupMarkup(grid, winningGroups, explodedPositions = null)`

- Строится маппинг `symbolType → groupId`.
- Для каждой ячейки: если символ в выигрышной группе → `markup[row][col] = groupId`, иначе `0`.
- **Пометка скаттеров под взрывом:** если передан параметр `explodedPositions` (для событий с бомбой типа `explode`), для каждой позиции проверяется, является ли символ скаттером. Если да, в `markup[row][col]` устанавливается значение `-2` (скаттер под взрывом, не удалять).

### Шаг 5: Позиция бомбы

**Метод:** `findBombPosition(grid)`

- Поиск ячейки с `BOMB_SYMBOL_TYPE`. Возврат `{ row, col }` или `null`.

### Шаг 6: Соседи бомбы

**Метод:** `findBombNeighbors(row, col)`

- Все 8 соседних ячеек (включая диагонали) с проверкой границ. Возврат `[{row, col}, ...]`.

### Шаг 7: Позиции выигрышных символов по группам

**Метод:** `findWinningPositionsFromGroups(grid, winningGroups)`

- Для каждой группы по `symbolType` собираются все ячейки с этим типом в сетке.
- Возвращает `Set` строк `"row,col"`.

### Шаг 8: Удаление символов

**Метод:** `removeSymbols(grid, positions)`

- `positions` — `Set("row,col")`.
- Для каждой позиции в сетке ставится `-1`, остальное копируется. Возвращается новая сетка.
- **Важно:** скаттеры (`9`, `10`, `11`) **не включаются** в множество `positions` для удаления. Они остаются на поле при удалении выигрышных символов и при взрыве бомбы (помечаются в `groupMarkup` значением `-2`).

### Шаг 9: Уплотнение колонок

**Метод:** `compactColumns(grid)`

- Для каждой колонки: сбор непустых символов снизу вверх, размещение снизу вверх; сверху — `-1` и запись в `emptySpots`.
- **Результат:** `{ grid: compacted, emptySpots: [{row, col}, ...] }`.
- Логика совпадает с `CascadeManager.compactColumns()`.
- **Скаттеры:** скаттеры уплотняются вместе с остальными символами (падают вниз при наличии пустот выше). Они не удаляются и остаются на поле до конца каскада.

### Шаг 10: Заполнение пустых мест

**Метод:** `fillEmptySpots(grid, emptySpots, getNextSymbol, bombAlreadyUsed, isCascadeRefill = false)`

- Сортировка `emptySpots`: сначала по `col`, затем по `row`.
- Для каждого пустого места проверяется последовательно:
  1. **Бомба:** если можно (нет бомбы после уплотнения и бомба ещё не использована) — с вероятностью `bombRefillChance` (при `isCascadeRefill === false`) или `bombCascadeChance` (при `isCascadeRefill === true`) подставляется бомба (`8`).
  2. **Скаттер:** если бомба не была размещена, с вероятностью `scatterRefillChance` (при `isCascadeRefill === false`) или `scatterCascadeChance` (при `isCascadeRefill === true`) размещается скаттер случайного типа (`9`, `10` или `11`).
  3. **Обычный символ:** если ни бомба, ни скаттер не были размещены, используется `getNextSymbol(refillIndex)`.
- Максимум одна бомба за досыпание. Скаттеров может быть несколько (каждый с отдельным шансом).
- Возврат `{ grid: filled, bombUsed }`.
- **Параметр `isCascadeRefill`:** `true` при досыпке внутри цикла каскадов (используется `bombCascadeChance` и `scatterCascadeChance`), `false` при досыпке после спина (используется `bombRefillChance` и `scatterRefillChance`).

### Шаг 11: Расчёт выплат

**Методы:** `calculatePayouts(winningGroups)`, `_getPayoutsTable()`, `_getPayoutForCountAndSymbol(payoutsTable, count, symbolName)`

- Таблица выплат берётся из `payoutsConfig.payouts` или из самого `payoutsConfig`.
- Для каждой группы (кроме бомбы): по `count` и `symbolName` ищется выплата в таблице (ключи `"7"`, `"8"`, …; имена символов: `h1_lion`, `h2_bull`, `h3_bear`, `h4_wolf`, `l1_revolver`, `l2_bottle`, `l3_horseshoe`, `l4_cactus`).
- Если точного `count` нет (например 31), используется ближайший меньший ключ (например 30).
- **Результат:** `{ payouts: [...], totalPayout: number }`.

### Шаг 12: Подсчёт скаттеров

**Метод:** `countScatters(grid)`

- Подсчитывает общее количество скаттеров всех типов на поле.
- Возвращает объект:
  ```javascript
  {
    total: number,           // Всего скаттеров
    blue: number,            // Синих (индекс 9)
    gold: number,            // Золотых (индекс 10)
    red: number,             // Красных (индекс 11)
    positions: Array<{row, col, type}>  // Позиции всех скаттеров
  }
  ```

### Шаг 13: Поиск позиций скаттеров

**Метод:** `findScatterPositions(grid)`

- Находит все позиции скаттеров на поле.
- Возвращает `Set` строк вида `"row,col"` для использования в `removeSymbols`.

### Шаг 14: Создание события

**Метод:** `createEvent(grid, eventType, winningGroups, bombPosition, bombAlreadyUsed)`

- Строятся `groupMarkup`, `payouts`, `totalPayout` через `createGroupMarkup` и `calculatePayouts`.
- При создании `groupMarkup`: если событие с бомбой типа `explode` (`bombType === 'explode'`), передаются `explodedPositions` в `createGroupMarkup` для пометки скаттеров под взрывом значением `-2`.
- Формируется объект события: `event`, `grid`, `groupMarkup`, `winningGroups`, `payouts`, `totalPayout`.
- Если есть бомба:
  - при выигрыше: `bombType: 'multiplier'`, `bombPosition`, `multiplier`, `totalPayout *= multiplier`;
  - без выигрыша: `bombType: 'explode'`, `bombPosition`, `explodedPositions` (бомба + 8 соседей).
- Опционально добавляется `scatterCount` (количество скаттеров на поле) для информации.

### Шаг 15: Добавление информации о скаттерах в события

**Метод:** `createEvent(grid, eventType, winningGroups, bombPosition, bombAlreadyUsed)`

- В каждом событии автоматически добавляется информация о скаттерах на поле (если есть хотя бы один скаттер).
- Используется `countScatters(grid)` для получения данных.
- Информация включает:
  - `scatterCount` - общее количество скаттеров
  - `scatterBlue`, `scatterGold`, `scatterRed` - количество каждого типа
  - `scatterActivated` - флаг активации (true если `scatterCount >= scatterActivationCount`)
  - `scatterPositions` - позиции всех скаттеров (опционально, для отладки)

## 3. Генерация одного спина с каскадами

**Метод:** `generateSpinWithCascades(getSpinGrid, getRefillSymbol)`

### 3.1. Начальное поле и первый шаг

1. `currentGrid = getSpinGrid()`.
2. `winningGroups = findWinningGroups(currentGrid)`, `bombPosition = findBombPosition(currentGrid)`.
3. Тип события спина:
   - выигрыш + бомба → `spin-win-bomb`;
   - выигрыш → `spin-win`;
   - только бомба → `spin-bomb`;
   - иначе → `spin`.
4. В массив шагов добавляется `createEvent(currentGrid, spinEventType, winningGroups, bombPosition, …)`.
5. Если нет выигрыша и нет бомбы — возврат (один шаг `spin`).

### 3.2. Обработка после спина

- **Бомба без выигрыша:** удаляются бомба и соседи (`removeSymbols` по `explodedPositions`), `bombAlreadyUsed = true`. Скаттеры в зоне взрыва не удаляются (помечаются в `groupMarkup` значением `-2`).
- **Выигрыш (с бомбой или без):** `winningPositions = findWinningPositionsFromGroups(...)`; при наличии бомбы в позиции удаления добавляется ячейка бомбы. Затем `currentGrid = removeSymbols(currentGrid, winningPositions)`. Скаттеры не включаются в `winningPositions` и не удаляются.
- Уплотнение: `compactColumns(currentGrid)`. Скаттеры уплотняются вместе с остальными символами (падают вниз).
- Досыпание: `fillEmptySpots(..., getRefillSymbol(0, refillIndex), bombAlreadyUsed, false)` (используется `bombRefillChance` и `scatterRefillChance`). Новые скаттеры могут появиться в пустых местах.
- Обновление: `currentGrid = filled`, пересчёт `winningGroups` и `bombPosition` на новой сетке. Подсчёт скаттеров через `countScatters`.

### 3.3. Завершение или цикл каскадов

- Если после досыпания нет выигрыша и нет бомбы — добавляется шаг `cascade` с текущей сеткой и возврат.
- Иначе запускается цикл каскадов.

### 3.4. Цикл каскадов

На каждой итерации:

1. Тип каскада: выигрыш+бомба → `cascade-win-bomb`, выигрыш → `cascade-win`, только бомба → `cascade-bomb`, иначе → `cascade`.
2. В шаги добавляется `createEvent(currentGrid, cascadeEventType, winningGroups, bombPosition, …)`.
3. Если нет выигрыша и нет бомбы — проверка активации скаттеров и выход из цикла.
4. Обработка:
   - бомба без выигрыша: удаление бомбы и соседей (скаттеры не удаляются, помечаются в `groupMarkup` значением `-2`);
   - выигрыш: удаление выигрышных (при наличии бомбы — бомба тоже в множестве удаления; скаттеры не удаляются).
5. Уплотнение и досыпание (`compactColumns`, `fillEmptySpots` с `getRefillSymbol(cascadeStepIndex, refillIndex)`, `isCascadeRefill = true` для использования `bombCascadeChance` и `scatterCascadeChance`). Скаттеры уплотняются вместе с остальными символами, новые скаттеры могут появиться при досыпке.
6. Обновление `currentGrid`, `winningGroups`, `bombPosition`, увеличение `cascadeStepIndex`. Подсчёт скаттеров через `countScatters`.
7. **Информация о скаттерах:** информация о скаттерах (включая флаг активации `scatterActivated`) автоматически добавляется в каждое событие через `createEvent`. В последнем событии спина или каскада (когда нет выигрыша и нет бомбы) флаг `scatterActivated` указывает на активацию бонуса при `scatterCount >= scatterActivationCount` (по умолчанию 4).

**Результат:** массив шагов сценария для одного спина.

## 4. Генерация полного сценария

**Метод:** `generateScenario(spinCount)`

1. `reset()` — очистка сценария.
2. **Высоковолатильность:** счётчик `simpleSpinsCount` для отслеживания сухих спинов подряд.
3. Для каждого из `spinCount` спинов:
   - **Гарантия минимума сухих спинов:** если `simpleSpinsCount < minSimpleSpinsBeforeWin` (по умолчанию 2), то `getSpinGrid = () => generateGridWithoutWinsAndBombs()` (гарантированно сухой спин), `simpleSpinsCount++`.
   - **Гарантия хотя бы одного простого spin:** если это последний спин и `simpleSpinsCount === 0`, то `getSpinGrid = () => generateGridWithoutWinsAndBombs()`.
   - **Вероятность сухого спина:** иначе с вероятностью `simpleSpinChance` (по умолчанию 0.6) выбирается сухой спин (`generateGridWithoutWinsAndBombs()`), `simpleSpinsCount++`; иначе — обычный спин (`generateRandomGrid()`), `simpleSpinsCount = 0`.
   - `generateGridWithoutWinsAndBombs()`: до `maxAttempts` раз генерируется сетка без бомбы (`generateRandomGrid(false)`); подходит первая без выигрышей (`findWinningGroups` пустой).
   - Вызов `generateSpinWithCascades(getSpinGrid, (cascadeStepIndex, refillIndex) => Math.floor(Math.random() * symbolCount))`.
   - Все полученные шаги добавляются в общий сценарий.
4. Возврат полного массива шагов.

**Параметры высоковолатильности:**
- `minSimpleSpinsBeforeWin` (по умолчанию 2) — минимум сухих спинов подряд перед разрешением выигрыша.
- `simpleSpinChance` (по умолчанию 0.6) — вероятность сухого спина после минимума (60% сухих, 40% с шансом на каскад).

## 5. Структура событий

### Общие поля всех событий

Все события содержат следующие базовые поля:
- `event` - тип события (`spin`, `spin-win`, `cascade`, `cascade-win` и т.д.)
- `grid` - сетка символов `number[][]`
- `groupMarkup` - разметка выигрышных групп `number[][]`
- `winningGroups` - массив выигрышных групп
- `payouts` - массив выплат
- `totalPayout` - общая выплата

Если на поле есть скаттеры, добавляются поля:
- `scatterCount` - общее количество скаттеров
- `scatterBlue` - количество синих скаттеров (индекс 9)
- `scatterGold` - количество золотых скаттеров (индекс 10)
- `scatterRed` - количество красных скаттеров (индекс 11)
- `scatterActivated` - флаг активации (true если `scatterCount >= scatterActivationCount`, по умолчанию 4)
- `scatterPositions` - опционально, массив позиций всех скаттеров `Array<{row, col, type}>`

### Структура событий с бомбой

### spin-win-bomb / cascade-win-bomb

```javascript
{
  event: 'spin-win-bomb',  // или 'cascade-win-bomb'
  bombType: 'multiplier',
  bombPosition: { row, col },
  multiplier: 5,
  grid: number[][],        // сетка до удаления выигрышных и бомбы
  winningGroups: [...],
  groupMarkup: number[][],
  payouts: [...],          // выплаты до умножения
  totalPayout: number,     // выплаты после умножения (×5)
  // Информация о скаттерах (если есть на поле):
  scatterCount: number,    // общее количество скаттеров
  scatterBlue: number,    // синих скаттеров
  scatterGold: number,     // золотых скаттеров
  scatterRed: number,      // красных скаттеров
  scatterActivated: boolean, // true если scatterCount >= scatterActivationCount (по умолчанию 4)
  scatterPositions: Array<{row, col, type}>  // опционально, позиции всех скаттеров
}
```

Бомба удаляется **вместе** с выигрышными символами в одном шаге.

### spin-bomb / cascade-bomb

```javascript
{
  event: 'spin-bomb',  // или 'cascade-bomb'
  bombType: 'explode',
  bombPosition: { row, col },
  explodedPositions: [{ row, col }, ...],  // бомба + до 8 соседей
  grid: number[][],    // сетка ДО взрыва
  winningGroups: [],
  groupMarkup: number[][],  // скаттеры под взрывом помечены значением -2
  payouts: [],
  totalPayout: 0,
  // Информация о скаттерах (если есть на поле):
  scatterCount: number,
  scatterBlue: number,
  scatterGold: number,
  scatterRed: number,
  scatterActivated: boolean,
  scatterPositions: Array<{row, col, type}>
}
```

Следующий шаг в сценарии — всегда `cascade` или `cascade-win` с сеткой **ПОСЛЕ** взрыва и досыпания.

### Информация о скаттерах в событиях

Информация о скаттерах добавляется во все события (если есть хотя бы один скаттер на поле):

```javascript
{
  event: 'cascade',  // или 'spin', 'spin-win', 'cascade-win' и т.д.
  // ... другие поля события ...
  scatterCount: number,       // Всего скаттеров
  scatterBlue: number,        // Синих
  scatterGold: number,        // Золотых
  scatterRed: number,         // Красных
  scatterActivated: boolean,  // true если scatterCount >= 4
  scatterPositions: Array<{row, col, type}>  // Опционально, позиции всех скаттеров
}
```

Флаг `scatterActivated` позволяет игровой логике определить, нужно ли активировать бонус (фриспины).

## 6. Выплаты (payouts)

- Источник: `payoutsConfig` (например из `payouts.json`). Таблица: `payoutsConfig.payouts` или сам объект с ключами `"5"`, `"6"`, … `"30"` и именами символов.
- Имена символов в таблице должны совпадать с `symbolNames` генератора: `h1_lion`, `h2_bull`, `h3_bear`, `h4_wolf`, `l1_revolver`, `l2_bottle`, `l3_horseshoe`, `l4_cactus`.
- Для каждого выигрыша по группе берётся выплата по `count` и `symbolName`; при отсутствии точного `count` используется ближайший меньший ключ.
- В каждом шаге с выигрышем заполняются `payouts` и `totalPayout`; при бомбе-множителе `totalPayout` уже с учётом ×5.

## 7. Важные детали реализации

### Порядок заполнения пустых мест
- Сначала по колонке (0→5), затем по ряду (0→4). Совпадает с порядком в CascadeManager.

### Уплотнение колонок
- Совпадает с `CascadeManager.compactColumns()`: сбор снизу вверх, размещение снизу вверх.

### Выигрышные группы
- Все символы одного типа 7+ на поле (без учёта соседства). Бомба и скаттеры не участвуют в группах.

### Бомба
- Максимум одна бомба за одно насыпание. При выигрыше с бомбой — бомба удаляется вместе с выигрышными (multiplier). При взрыве — бомба + до 8 соседей, затем уплотнение и досыпание.
- **Шансы появления:**
  - На спине: `bombSpinChance` (по умолчанию 3%).
  - При досыпке после спина: `bombRefillChance` (по умолчанию 1%).
  - При досыпке внутри каскада: `bombCascadeChance` (по умолчанию равен `bombRefillChance`, можно задать отдельно).

### Скаттеры
- Три типа скаттеров: синий (9), золотой (10), красный (11).
- Могут появляться на спине и при досыпке (независимо от бомбы).
- **Неуязвимость:** скаттеры НЕ удаляются при взрыве бомбы (помечаются в `groupMarkup` значением `-2`) и НЕ удаляются вместе с выигрышными символами.
- **Активация:** в конце каскада проверяется общее количество скаттеров; при 4+ флаг `scatterActivated: true` добавляется в последнее событие спина или каскада.
- Не участвуют в выигрышных группах и не учитываются в выплатах.
- **Spine анимации:** скаттеры используют постоянный Spine экземпляр с анимациями `idle` (постоянно), `bounce` (при приземлении), `hit` (после насыпания в событиях `spin` и `cascade`), `idle_null` (после завершения `hit`).

### Формат сетки
- Генератор: `grid[row][col]`. CascadeManager: `grid[col][row]`; при загрузке сценария выполняется конвертация.

---

## 8. Использование сценария в CascadeManager

- При загрузке: конвертация `grid[row][col]` → `grid[col][row]`.
- Для `spin-win-bomb` и `cascade-win-bomb`: в список символов на удаление добавляется и бомба по `bombPosition` (CascadeManager удаляет выигрышные и бомбу одним шагом).
- Для `spin-bomb` и `cascade-bomb`: по `explodedPositions` удаляются бомба и соседи (но не скаттеры — они помечены в `groupMarkup` значением `-2`), затем переход к следующему шагу (`cascade`/`cascade-win`).
- Информация о скаттерах (включая флаг `scatterActivated`) доступна в каждом событии для обработки активации бонуса (фриспины) игровой логикой.

## 9. Логика работы скаттеров

### Генерация скаттеров

1. **На спине:**
   - В `generateRandomGrid(allowBomb = true, allowScatter = true)` после генерации бомбы (если разрешена) добавляется логика генерации скаттеров.
   - Для каждой ячейки с шансом `scatterSpinChance` (по умолчанию 3%) может быть размещён скаттер случайного типа (9, 10 или 11).
   - Можно разместить несколько скаттеров на одном поле (каждый с отдельным шансом).

2. **При досыпке:**
   - В `fillEmptySpots(..., isCascadeRefill = false)` для каждого пустого места с шансом `scatterRefillChance` (при `isCascadeRefill === false`) или `scatterCascadeChance` (при `isCascadeRefill === true`) может быть размещён скаттер.
   - Случайно выбирается тип скаттера (9, 10 или 11).

### Неуязвимость скаттеров

1. **При взрыве бомбы:**
   - В `createGroupMarkup` при создании события с бомбой типа `explode` передаются `explodedPositions`.
   - Для каждой позиции из `explodedPositions` проверяется, является ли символ скаттером.
   - Если да, в `groupMarkup[row][col]` устанавливается значение `-2`.
   - В `CascadeManager._handleBombExplode` при обработке `explodedPositions` проверяется `groupMarkup[row][col]`.
   - Если значение `-2`, символ пропускается (не добавляется в `symbolsToRemove`).

2. **При удалении выигрышных символов:**
   - В `removeSymbols` скаттеры не включаются в множество позиций для удаления.
   - Скаттеры остаются на поле до конца каскада.

### Перемещение скаттеров в сценарии

1. **При уплотнении колонок (`compactColumns`):**
   - Скаттеры уплотняются вместе с остальными символами (падают вниз при наличии пустот выше).
   - Они сохраняют свой тип (9, 10 или 11) и позицию в колонке.
   - Скаттеры не удаляются при уплотнении, они просто перемещаются вниз.

2. **При досыпке (`fillEmptySpots`):**
   - Новые скаттеры могут появиться в пустых местах после уплотнения.
   - Существующие скаттеры остаются на своих позициях (не заменяются новыми символами).
   - Новые скаттеры размещаются в пустых местах с соответствующими шансами (`scatterRefillChance` или `scatterCascadeChance`).

3. **При удалении выигрышных символов (`removeSymbols`):**
   - Скаттеры не участвуют в выигрышных комбинациях (типы 9, 10, 11 не входят в `winningGroups`), поэтому множество позиций на удаление формируется только по обычным символам (0–7).
   - В `removeSymbols` скаттеры явно исключаются: если позиция есть в `positions`, но символ — скаттер, ячейка не очищается. Скаттеры остаются на поле и участвуют в уплотнении.

4. **При взрыве бомбы:**
   - Скаттеры, попавшие в зону взрыва, помечаются в `groupMarkup` значением `-2`.
   - Они не удаляются и остаются на поле после взрыва.
   - При уплотнении после взрыва скаттеры падают вниз вместе с остальными символами.

### Активация скаттеров

- В каждом событии автоматически добавляется информация о скаттерах через `createEvent`.
- Метод `createEvent` вызывает `countScatters(grid)` и добавляет в событие:
  - `scatterCount` - общее количество скаттеров
  - `scatterBlue`, `scatterGold`, `scatterRed` - количество каждого типа
  - `scatterActivated` - флаг активации (true если `scatterCount >= scatterActivationCount`, по умолчанию 4)
  - `scatterPositions` - позиции всех скаттеров (опционально)
- Информация о скаттерах включается в последнее событие спина или каскада (когда нет выигрыша и нет бомбы).
- Игровая логика может проверить флаг `scatterActivated` для активации бонуса (фриспины).
