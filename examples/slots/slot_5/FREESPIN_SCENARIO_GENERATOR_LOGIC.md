# Логика генератора сценариев фриспина (FreeSpinScenarioGenerator)

**Отдельный документ** — вся логика генератора фриспина описана здесь. Базовые типы событий и формат сетки приведены в разделе 0; для деталей обычной игры (V3) см. [SCENARIO_GENERATOR_LOGIC.md](SCENARIO_GENERATOR_LOGIC.md).

Файл генератора: [FreeSpinScenarioGenerator.js](FreeSpinScenarioGenerator.js).

---

## 0. Базовые понятия (общие с обычной игрой)

- **Сетка**: `grid[row][col]`, строки 0…4, колонки 0…5. Значения: 0…7 — обычные символы, 8 — бомба, 9/10/11 — скаттеры (blue/gold/red), −1 — пусто.
- **Типы событий**: `spin`, `spin-win`, `spin-win-bomb`, `spin-bomb`, `cascade`, `cascade-win`, `cascade-win-bomb`, `cascade-bomb`. Бомба с выигрышем — multiplier (×5), бомба без выигрыша — explode (бомба + 8 соседей).
- **Скаттеры**: не удаляются при взрыве и с выигрышными. Каждый скаттер на поле даёт +1 фриспин (при попадании на поле); в конце раунда к счётчику фриспинов добавляется количество скаттеров на поле.
- **Один раунд** = один спин (насыпание сетки) + каскады до завершения (удаление выигрышных/взрыв, уплотнение, досыпание, повтор).

---

## 1. Назначение

- Генерация **полного сценария бонусной игры**: несколько раундов фриспина подряд.
- Структура событий (spin, spin-win, cascade, …) **та же**, что в V3 — автопрожим спинов в бонусе делает **игра** (CascadeManager), а не генератор.
- В сценарии явно отражены: признак бонуса, счётчик фриспинов, активные сундуки (минимум 1), мультипликатор жёлтого сундука при взрывах бомб.

---

## 2. Отличия от обычного сценария (V3)

| Аспект | Обычная игра (V3) | Фриспин |
|--------|-------------------|--------|
| Спин | Каждый спин — отдельное нажатие | Та же структура событий; автопрожим — ответственность игры |
| Счётчик | Нет | Фриспин убавляет только событие спин (spin, spin-win, spin-bomb, spin-win-bomb) — по одному за раунд; каждый скаттер на поле даёт +1 (в конце раунда). |
| Лимит | Нет | Внутренняя страховка `maxFreeSpinRounds`; в сценарий не пишется; сценарий до 0 за счёт пониженных шансов скаттеров |
| Контекст | Обычный сценарий | `isBonus: true`, метаданные в первом шаге |
| Сундуки | Не в сценарии | `activeChests` — массив цветов (red/blue/yellow), длина ≥ 1 |
| Жёлтый сундук | — | `yellowChestMultiplier` увеличивается при каждом срабатывании бомбы |

---

## 3. Формат сценария

### 3.1 Метаданные (первый шаг `bonus-init`)

Первый элемент массива сценария — служебное событие:

```javascript
{
  event: 'bonus-init',
  isBonus: true,
  activeChests: ['red', 'yellow'],
  yellowChestMultiplierPerBomb: 5   // множитель за одну бомбу (как в V3), в шагах накапливается сумма мультипликаторов
}
```

- **activeChests** — какие сундуки активны в бонусе (минимум 1). Означает также, что **в начале бонусной игры эти сундуки уже на 3 уровне** (открытый сундук); см. [CHEST_MANAGER.md](CHEST_MANAGER.md).
- **yellowChestMultiplierPerBomb** — множитель, который даёт одна бомба (обычно 5, из V3); в шагах **yellowChestMultiplier** — это накопленная **сумма мультипликаторов бомб**, а не количество бомб.
- В сценарий **не** записываются `initialFreeSpins` и `maxFreeSpinRounds` — сценарий логически идёт до 0 фриспинов: каждый раунд −1; каждый скаттер на поле даёт +1 фриспин. Стартовое значение видно по полю `freeSpinsRemaining` в первом шаге спина.

### 3.2 Остальные шаги (spin / cascade)

Каждый шаг — обычное событие V3 плюс поля:

- **freeSpinsRemaining** — счётчик фриспинов на начало этого шага.
- **roundIndex** — номер раунда (0, 1, 2, …).
- **isAutoSpin** — `true` для roundIndex > 0.
- **yellowChestMultiplier** — накопленная сумма **мультипликаторов бомб** (если жёлтый в `activeChests`): при каждой бомбе добавляется множитель этой бомбы (для win+bomb — `step.multiplier`, для explode — `bombMultiplier` из V3, обычно 5).

События без `grid` (например `bonus-init`) при визуализации пропускаются.

---

## 4. Логика генератора

### 4.1 Входные параметры

- **initialFreeSpins** (по умолчанию 10).
- **maxFreeSpinRounds** — только внутренняя страховка от бесконечного цикла (по умолчанию 200); в сценарий не записывается; сценарий должен доходить до 0 фриспинов за счёт пониженных шансов скаттеров.
- **activeChests** — массив `['red'|'blue'|'yellow']`, длина ≥ 1; если не передан — выбирается случайно минимум один цвет.
- Конфиг сетки/каскадов/выплат — тот же что у V3.
- Жёлтый сундук: накопление идёт по **мультипликаторам бомб** (не по количеству бомб): за каждую бомбу к `yellowChestMultiplier` добавляется множитель бомбы (win+bomb — `step.multiplier`, explode — `bombMultiplier` из V3, обычно 5). В bonus-init поле `yellowChestMultiplierPerBomb` задаёт этот множитель за одну бомбу (для совместимости с игрой).
- **scatterSpinChanceFreeSpin**, **scatterRefillChanceFreeSpin**, **scatterCascadeChanceFreeSpin** (по умолчанию 0.005) — пониженные шансы скаттеров во время генерации фриспина, чтобы сценарий доходил до 0 фриспинов (каждый скаттер даёт +1, при высоких шансах счётчик растёт и фриспины не заканчиваются).

### 4.2 Алгоритм

1. Добавить шаг `bonus-init` с метаданными (без initialFreeSpins и maxFreeSpinRounds).
2. Инициализация: `freeSpinsRemaining = initialFreeSpins`, `roundIndex = 0`, `yellowChestMultiplier = 0`.
3. На время генерации **снизить шансы скаттеров** у V3 (по умолчанию 0.005), чтобы сценарий доходил до 0 фриспинов.
4. Цикл **пока** `freeSpinsRemaining > 0` **и** `roundIndex < maxFreeSpinRounds` (maxFreeSpinRounds — только страховка, в сценарий не пишется):
   - Сгенерировать один раунд через V3 (`generateSpinWithCascades`).
   - Для каждого шага раунда: добавить `freeSpinsRemaining`, `roundIndex`, `isAutoSpin`, при необходимости `yellowChestMultiplier` (при бомбе добавляется множитель бомбы, если активен жёлтый сундук).
   - По завершении раунда: `freeSpinsRemaining -= 1`; затем добавляем к счётчику количество скаттеров на поле в последнем шаге раунда (каждый скаттер даёт +1 фриспин).
   - Проверить условия выхода; иначе `roundIndex++` и следующий раунд.
5. Восстановить шансы скаттеров V3. Результат: массив `[bonus-init, ...шаги]`.

### 4.3 Переиспользование V3

- Генератор создаёт экземпляр `ScenarioGeneratorV3` с переданным конфигом и вызывает у него `generateSpinWithCascades(getSpinGrid, getRefillSymbol)` для каждого раунда.
- Сетка для спина: случайная (как в V3), без принудительной «сухости» по умолчанию.

---

## 5. Жёлтый сундук и бомбы

- **spin-bomb / cascade-bomb** (bombType `'explode'`): каждая такая бомба даёт +1 (или по конфигу) к `yellowChestMultiplier`, если `'yellow'` в `activeChests`.
- **spin-win-bomb / cascade-win-bomb** (bombType `'multiplier'`): по конфигу можно также увеличивать `yellowChestMultiplier` на то же значение (жёлтый «забирает» множитель с бомбы).

---

## 6. Конечность фриспинов

**Правило счётчика:** минус 1 фриспин даёт только событие спин (spin, spin-win, spin-bomb, spin-win-bomb) — в каждом раунде ровно одно такое событие. Плюс 1 фриспин за каждый скаттер на поле в конце раунда.

- Сценарий логически идёт **до 0 фриспинов**: каждый раунд −1; плюс столько фриспинов, сколько скаттеров на поле в конце раунда. В сценарий не пишутся начальное значение и лимит раундов — они не нужны для воспроизведения.
- Во время генерации используются **пониженные шансы скаттеров** (по умолчанию 0.005), чтобы скаттеров не было слишком много и спины заканчивались. Тест: `node test_freespin_generator_quick.mjs`.
- В коде остаётся страховка `maxFreeSpinRounds` (внутренний лимит раундов), чтобы цикл не мог быть бесконечным; в JSON сценария это не попадает.

---

## 7. Тесты для настройки

- **Конечность**: при заданных `initialFreeSpins`, `maxFreeSpinRounds` и конфиге генератор всегда завершается; число раундов ≤ `maxFreeSpinRounds`.
- **Без скаттеров**: при нулевых шансах скаттеров число раундов = `min(initialFreeSpins, maxFreeSpinRounds)`.
- **Активные сундуки**: в каждом сценарии `activeChests.length >= 1`, все элементы из `['red','blue','yellow']`.
- **Жёлтый мультипликатор**: при активном жёлтом сундуке в шагах с бомбой поле `yellowChestMultiplier` увеличивается согласно конфигу.

---

## 8. Совместимость с интерфейсом

- Генератор экспортирует массив в том же стиле, что и V3: `scenario` (массив шагов), `formatCompactJSON()`, `exportToJSON()`, `downloadScenario(filename)`.
- Метод `findWinningPositions(grid)` делегируется экземпляру V3 для совместимости с визуализатором.
- В режиме «Фриспин» в UI отображается выбор: начальные фриспины, макс. раундов, активные сундуки (чекбоксы, минимум один выбран).

При изменении логики генератора обновите этот документ и проверьте согласованность с CascadeManager при использовании фриспин-сценариев.
